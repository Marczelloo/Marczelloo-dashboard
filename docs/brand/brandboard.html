Obsidian Console
for one Raspberry Pi.

Marczelloo Dashboard is a private control room for the projects that live on a single machine. The interface is calm when everything is up and unmistakable when something is not: near-black surfaces, hairline structure, and crimson reserved for the one thing that needs you.

Mark

The Frame ring M. The rounded tile is a panel; its outline is a progress ring read clockwise from the top-left, running from white into a single crimson segment. It says what the product does, watching things run to completion, and keeps the M that has always identified it.

Construction · 64 unit grid
  • Tile radius 15/64. Ring inset 10, radius 11, stroke 5. Letter optically centred on the ring, cap height 15.
  • Ring reading: white 0 → 60 %, gap 3 %, crimson 63 → 76 %, remainder at 16 % white.
Sizes · 16 px uses its own heavier cut

Do

  • Animate the ring once: it fills on first load of the app and while the dashboard deploys itself.
  • Keep clear space of one ring stroke (5/64 of the tile) on every side.
  • Use the 16 px cut for favicons; never scale the 64 grid below 20 px.

Don't

  • Loop the ring animation, rotate the mark, or use the ring as a spinner.
  • Move the crimson segment, add a second colour, or recolour the letter.
  • Set the wordmark in anything but Geist 600, or track it out.

Colour

Restrained: cool near-black neutrals do almost all the work. Crimson is a signal, not a theme: the active page, the primary action, focus, and anything in progress. Status colours only ever describe real system state, and always travel with an icon or a word.

Typography

One family carries the whole product. Geist is neutral and dense enough for tables yet has a clear technical voice; Geist Mono is used only for machine data: commits, domains, ports, durations, logs and keyboard keys. Fixed rem steps, 1.14–1.2 apart; tabular numerals wherever numbers update.

Motion

Motion carries state: something opened, moved, finished or is still running. It is fast, eases out, and never makes the owner wait. One signature moment: a project that needs attention rises to the top of the fleet and unfolds. Everything collapses to instant fades under reduced motion.

Duration tokens
instant · 90Press scale, checkbox, copy feedback
quick · 140Hover fills, colour, border, focus ring
base · 200Tabs indicator, menus, row actions reveal
panel · 260Row detail unfold, drawer, toast, palette
layout · 420Row reorder in the fleet, route change
ease-outcubic-bezier(.16, 1, .3, 1)Default for everything that enters or responds.
ease-in-outcubic-bezier(.65, 0, .35, 1)Things already on screen that move to a new place.
springcubic-bezier(.34, 1.4, .64, 1)Only for small confirmations: a check, a count ticking.

Rules

  • Exits run at ~70 % of the entrance duration. Hover-out is slower than hover-in never.
  • Stagger only the first load of a list: 30 ms per row, capped at 8 rows.
  • Route change: content fades up 4 px over 200 ms; the shell never moves.
  • Live pulse (1.8 s) marks operations that are running right now, nothing else.

Never

  • Page-load choreography, parallax, or animating numbers that did not change.
  • Layout motion longer than 420 ms or bounces on large surfaces.
  • Hiding content until an animation runs: default state is visible.

Layout

One shell for every page: a 232 px sidebar, a 52 px top bar, and content up to 1440 px with 24 px gutters. Pages share one header component (title, context, actions) instead of hand-built headers. Desktop first; the phone gets the same pages in one column.

≥ 1280 · desktopFull sidebar with labels, two-column regions (fleet 1fr, side panels ⅓).
768–1279 · laptop / tabletSidebar collapses to a 56 px icon rail (also on demand); side panels drop below.
< 768 · phoneSidebar becomes a drawer from the top bar; tables become stacked rows with actions always visible.

Voice

English, sentence case, plain. Name the thing and the action. Errors say what happened and what to do next. Numbers and times are exact.
